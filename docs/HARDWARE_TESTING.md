# CloudTune NX 实机验收

这是待用户执行的实机验收步骤，不是已通过的结果。模拟器和桌面测试不能
代替 Atmosphère 游戏内后台播放验证。

记录 `dist/` 包的 SHA-256、主机型号、HOS、Atmosphère、HBMenu 和
Tesla / Ultrahand 版本，保留同包的 ELF 符号。首次测试先关闭其他非必要
第三方后台模块，随后再验证日常组合。

| 场景 | 操作与通过条件 |
| --- | --- |
| 首次启动 | R + 游戏进入 HBMenu；NRO 显示中文、方向键与触摸均能操作 |
| 扫码登录 | 扫码、手机确认、界面显示昵称；退出重开仍能读到会话 |
| 二维码异常 | 不扫码等待过期、刷新；扫码后取消；界面明确状态且不崩溃 |
| 短信登录 | 手动选择发送一次验证码，输入后登录；错误验证码有提示 |
| 收藏读取 | 对照官方客户端核对喜欢、创建/收藏歌单、专辑、电台、云盘 |
| 收藏写入 | 使用可恢复的测试歌曲/歌单收藏后撤销，核对官方客户端 |
| 正常播放 | 免费可播放曲目连续播放至少 30 分钟，自动切歌正常 |
| 会员 / 试听 | 对照账号权益，试听明确提示，不将 45 秒试听标成完整歌曲 |
| 黑胶与歌词 | 唱片旋转，暂停时冻结；LRC 对齐当前播放时间 |
| Seek | 前后跳转、缓冲中跳转、临近结束跳转，无持续静音或死锁 |
| 后台交接 | 播放栏显示 BGM；退出 NRO，声音持续；打开游戏后继续播放 |
| 覆盖层 | 游戏中打开、关闭至少 20 次；切歌、暂停、音量、随机/循环工作 |
| 重开 NRO | 播放不中断；进度/标题与覆盖层一致，不出现双重音轨 |
| 服务异常 | 停止服务后有明确断连提示；重新选择歌曲可以恢复 |
| 资源竞争 | 至少测试一款高内存游戏及平时启用的其他后台模块 |
| 系统状态 | 睡眠/唤醒、插拔底座、切换耳机/蓝牙；记录声音与服务状态 |
| 网络异常 | 断网、恢复、切 Wi-Fi、缓存已命中/未命中，错误可恢复 |
| SD 异常 | 剩余空间不足、部分缓存中断，不播放损坏缓存、不破坏其他文件 |
| 退出账号 | 本地 cookie 清除，后台下一次解析不再使用已退出的身份 |
| 更新 | 更换三类二进制后重启；已有收藏和设置保留，无 ABI 混用 |

## AirPlay 1 接收

以下项目均待实机执行。另记录发送设备型号、操作系统版本、发送 App、路由器型号、
Wi-Fi 频段和音频输出方式。首次使用同一普通局域网；随后再验证日常网络环境。
操作说明见 [AirPlay 音频接收](AIRPLAY.md)。桌面加密协议测试通过不能代替 Apple
发送端和 Switch `audout` 的实际兼容性结果。

| 场景 | 操作与通过条件 |
| --- | --- |
| 首次启动与发现 | 无旧 AirPlay 设置时打开 NRO；接收默认开启，显示实际名称和 IP；发送设备可以发现并选择 CloudTune NX |
| 实际手机投送 | 使用支持经典音频投送的 Apple 设备，播放已知测试音频；有声、双声道正常，无明显失真；记录发送 App 和系统版本 |
| 持续播放 | 连续投送至少 30 分钟；记录掉音、延迟漂移、服务错误及内存占用，不出现持续增长或崩溃 |
| 关闭偏好 | 在设置关闭接收，确认当前会话结束、无法建立新会话；退出重开及重启主机后仍关闭 |
| 重新开启 | 再次开启后状态就绪，设备身份稳定，发送端可以重新连接；检查设置页实际状态与监听一致 |
| 后台独立接收 | 确认 BGM 模式，投送中退出 NRO并打开游戏；音频继续。发送端主动断开后，在 NRO 关闭期间重新投送也能建立会话 |
| 重开应用 | 后台投送时重开 NRO；不抢占音频、不出现重复设备或双重音轨；设置显示同一后台会话 |
| 前台模式 | 在未安装后台服务的测试环境运行；NRO 内能接收，退出后本地接收停止，界面提示与实际一致 |
| 与网易云交接 | 网易云播放中开始投送，确认只有投送音频；结束投送后原队列及位置保留为暂停，按播放从原位置继续 |
| 主动切回音乐 | 投送期间选择网易云曲目、切歌或停止；投送先断开，音乐控制生效，无两路音频混合 |
| 暂停与音量 | 通过 NRO 或覆盖层暂停、恢复、调音量；恢复不重放暂停期间的旧音频，发送端和本地静音均生效 |
| 断开会话 | 在设置选择断开；当前音频结束并反馈结果，接收开关保持开启，之后可由发送端重新连接 |
| 单发送端 | 一个发送端连接时使用第二个发送端尝试连接；已有会话不被夺取，拒绝后服务仍可用 |
| 网络与端口恢复 | 断网后恢复、切换 Wi-Fi 或 IPv4 地址；状态更新，重新发现后可重连。受控占用端口再释放，自动重试恢复，无需关开开关 |
| 反复连接 | 完成至少 20 次连接、断开及开关切换；无死锁、端口遗留或持续内存增长 |
| 输出与系统状态 | 切换耳机、蓝牙、底座及睡眠/唤醒；记录会话和声音状态。休眠期间持续接收不是通过条件，唤醒后应可恢复使用 |
| 资源竞争 | 在高内存游戏及日常后台模块组合中投送；核对 16 MiB 服务堆配置是否足够，保留崩溃时对应 ELF |
| 旧服务兼容 | 在可恢复的测试环境使用旧后台组件；音乐仍能控制，AirPlay 明确提示更新，不另建冲突接收器；同步更新并重启后工具可用 |

记录每项的通过、失败或未测，以及复现步骤；请勿将未执行项目标为通过。
报告网络问题时可描述接口和地址变化，避免附上完整私有数据目录、账号会话或音频内容。

出现问题时先记录场景、时间、错误提示和模块 ID。不要反复重试短信发送，
不要将 cookie、二维码或账号响应附到公开 issue。
