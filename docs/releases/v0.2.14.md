# CloudTune NX v0.2.14 · 覆盖层共存时的受限内存启动

实机 v0.2.13 在 CloudTune 与 Tesla／Ultrahand 加载器同时开启时，剩余约
5.18–5.41 MiB。旧版要求至少 10.25 MiB，因此在注册 IPC 前超时退出，
前台一直显示后台未就绪。本版修复这项启动策略限制。

- 新增受限模式：连续 5 秒剩余至少 5 MiB 时，可使用最多 2 MiB 的后台堆，
  并在分配／启动工作前检查 3 MiB 系统策略余量。
- 内存充足时保留普通模式：8 MiB 系统余量，后台堆按需增长、上限 16 MiB。
- 模式在首次分配前锁定；受限模式不能在播放时继续扩堆。保留 HOME 等待、
  线程／事件／会话检查、超时退出和失败清理；不修改系统内存池或加载器。
- 启动日志新增 `memory-policy`、`memory-reserve-bytes` 和 `heap-limit-bytes`。

请一起更新 NRO、后台 `exefs.nsp` 和 `CloudTune.ovl`，保留账号、设置和照片。
**保留 Tesla／Ultrahand 加载器自启**，它是游戏内打开覆盖层所必需的。
公开安装包仍默认按需启动；已明确启用 CloudTune 自启的用户可保留其
`flags/boot2.flag`，覆盖文件后必须重启才会运行新后台。

宿主与 UBSan 各 33 项测试、重点 ASan 检查、三组件编译及原生模拟器
受限堆播放测试通过。模拟器注入同样的剩余内存，验证 512 首生成队列、
首次 HTTPS MP3／AAC／FLAC、切歌和分配失败恢复；同一受限运行时也
通过生成的加密 ALAC 接收、音频输出和断开测试。

3 MiB 是软件策略余量，不是系统预留保证；大队列、复杂文件可能超出
2 MiB 堆预算。**实机冷启动、账号曲目、覆盖层及游戏共存仍需重启验收**。
详情见 [验证记录](../VALIDATION.md) 和 [安装说明](../INSTALLING.md)。
