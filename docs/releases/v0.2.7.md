# CloudTune NX v0.2.7 · 后台启动保护与内存修复

## 先恢复开机，再更新

**从 v0.2.6 或更早版本升级，必须先移除或改名旧文件：**

`sd:/atmosphere/contents/42000000004E434D/flags/boot2.flag`

建议改名为 `boot2.flag.disabled`。覆盖新 ZIP 不会删除这个旧文件。
保留 `config/netease-switch/` 中的账号、设置和缓存，不要删除其他系统模块。
仅将 `CloudTuneNX-0.2.7-sd.zip` 解压至 SD 根目录；symbols/docs 留在电脑上。

## 修改

- 完整包默认不再携带开机自启标志，打开 NRO 时使用已有的按需启动流程。后台启动成功后仍可退出 NRO、控制播放和接收 AirPlay；开机后首次打开 NRO 前，后台和 AirPlay 尚未运行。
- 后台 NPDM 改用系统内存池，补齐 libnx 传输内存清理所需的调用权限。
- 删除 AAC/ALAC 构建用不到的大尺寸 FFT 表，限制所有递归变换初始化的长度并拒绝越界请求。后台静态占用由约 34.9 MiB 降至 19.1 MiB，保留 16 MiB 运行时堆预算。补丁、原始上游源码和重建方法随 docs 包分发。
- 初始化失败改为记录错误并正常退出，仅释放已初始化资源；捕获运行时创建阶段的异常，避免这些错误直接调用致命中止。
- 新增 `config/netease-switch/background-startup.log`，记录可用阶段及错误码；SD 挂载以前的错误仅输出到调试通道。发布校验拒绝错误内存池、超过 22 MiB 的后台静态占用和默认开机自启包。

不修改账号、播放列表、IPC 协议及已确认的 UI。公开版不含私人照片。

## 验证与边界

本地 28/28 回归测试通过，包括逐个服务启动失败、清理、不可写日志、变换大小边界、AAC/ALAC、MP3/FLAC、UI 与 IPC。Switch 三组件构建成功。隔离 Eden 的实际 NRO 已验证启动、在线推荐加载、推荐首曲播放及暂停。

这是针对已发现启动风险的修复，**尚未取得本次用户崩溃的错误码或实机报告，未确认唯一根因，也未完成该设备的开机复测**。Eden 的 NRO 测试不能验证 Atmosphère 开机流程。如果禁用 CloudTune 自启后仍不能开机，保留崩溃报告，按[安装指南](https://github.com/tiansongyu/cloudtune-nx/blob/v0.2.7/docs/INSTALLING.md#recover-a-console-that-crashes-during-boot)恢复并反馈 Program ID、错误码及系统版本。
