# CloudTune NX v0.3.1 · AirPlay 通道与连接恢复（候选）

- 根据实机日志修复 UDP 通道缓冲分配不合理的问题：音频、重传、时钟、设备发现分别分配，资源紧张时有界缩小并重试；失败时释放全部部分分配，支持重新连接。
- 缩小各 UDP socket 的初始占用，BSD 传输内存由 240 KiB 调整为 152 KiB，避免扩大缓冲影响 AAC 解码和切歌。
- AirPlay 待机时释放未使用的 64 KiB 音频包缓冲，降低与后台音乐长时间共存时的内存压力。

- 修复未播放的探测连接阻塞同一手机真正播放连接、返回 `453` 的问题。
- 单次会话内存分配失败后保留发现与监听，手机可以重新连接；正在播放的会话仍禁止抢占。
- 增加有大小上限的接收和音频输出阶段日志，用于定位连接后无声，不记录账号、密钥或音频内容。
- 保留 v0.3.0 的后台播放优化、2 MiB 内存限制、系统资源检查和原有 IPC 接口。

主机与 UBSan 各通过 33 项测试，ASan 协议回归通过。独立 pyatv 客户端完成
探测连接交接后的实际 PCM 输出；Switch 原生模拟器通过身份校验、AAC 接管、
加密 ALAC、重复大封面、FLUSH 与 TEARDOWN，3,758 包零丢失。
开启 AirPlay 待机的原生接口压力测试通过 8,013 项断言，覆盖 30 轮播放控制、
3,000 次音量更新与 3,000 次状态查询，以及四次连续自动切歌；生产后台堆上限仍为 2 MiB。

首轮候选实机仍无声，新增日志确认 SETUP 阶段发生 `ENOBUFS (105)`，未开始解码。
第二轮候选已针对该路径修复，**手机到实机 Switch 的最终验收尚未完成**。
详情见[验证记录](https://github.com/tiansongyu/cloudtune-nx/blob/main/docs/VALIDATION.md)。
