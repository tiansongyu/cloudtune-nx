# CloudTune NX v0.2.13 · 环境识别与低内存播放修复

修复旧 Tesla／兼容覆盖层加载器下的 `检查环境 0x00004b59`，以及后台因资源不足退出后，前台仍停留在“后台未就绪”的问题。保留 Borealis/C++、现有账号、音质和 IPC 文件格式。

- 使用可验证的 Atmosphère 内核查询补充加载器标记；服务和进程均确认不存在后，可恢复前台播放。状态不明时仍避免两个播放器争用音频。
- 包含本地候选 v0.2.12 的标准 CMIF 工作线程、超时处理、重连和重复启动保护；v0.2.12 未公开发布。
- 队列只保留实际文本，减少常驻占用。M4A 避免重复探测；内存不足不再误报音频损坏。
- 网络下载与解码同时运行导致内存不足时，保留当前下载，完成后释放网络线程并重试解码一次。可随时停止或切歌；不会降低音质或重新下载同一文件。
- 启动预算由估算 4 MiB 校准为实测 2 MiB 加 256 KiB 余量。**8 MiB 系统余量、逐次扩堆保护、连续观察窗口均保留**，没有修改系统内存配额。

同时更新 `CloudTune.nro`、后台 `exefs.nsp` 和 `CloudTune.ovl`，然后完整重启。公开包不含私人照片，开机自启仍为可选。不要把旧组件与新组件混用。

在本次主机上，关闭五个额外模块后仍只剩约 5 MiB 共享内存，未达到安全启动条件。用户授权的本机复测配置进一步暂时关闭 Tesla／Ultrahand 加载器，只保留 CloudTune 自启；因此覆盖层暂不可用。此配置不包含在公开安装包内，可恢复。

原生模拟器限堆测试覆盖 512 首生成队列、首次 HTTPS MP3／AAC／FLAC、有效 PCM 和停止；AAC 在实际分配失败后恢复。宿主测试与构建范围见 [验证记录](../VALIDATION.md)。**实机后台启动、真实会员曲目、游戏共存和覆盖层控制仍需重启后验收**；2 MiB 测试不代表任意音频或最大长度队列都只占用该内存。
