# CloudTune NX v0.3.0 · 后台连续播放与 AirPlay

优化后台播放时的音频调度和连续切歌，修复 AirPlay 连接后因封面传输耗尽受限内存而断流的问题。

- 音频、接收、下载线程按播放需求调度，保留后台只使用核心 3 的限制。
- 音频输出使用 256 ms 有界缓冲和释放事件，减少轮询；密集音量更新不会持续挤占音频工作。
- 自动切歌保留上一首尾音和输出会话，提前初始化下一首；已缓存队列减少重建音频设备造成的间隙。
- AirPlay 封面分块消费，小音频包聚合后提交；减少常驻交接缓冲，及时回收下载线程。
- 保留 2 MiB 受限堆、自启资源检查、前台/覆盖层通信与账号隔离。

请覆盖安装配套 NRO、`exefs.nsp` 与覆盖层并重启 Switch。已有 CloudTune
`boot2.flag` 和 Tesla／Ultrahand 加载器自启标志应保留。公开安装包不包含私人照片；
公开包仍默认按需启动，已有自启安装不受影响。

主机测试与 UBSan 各通过 33 项；原生后台 IPC 压测通过 8,013 项断言，完成
30 轮播放控制及模拟负载下的连续切歌。2 MiB 堆限制下，AAC 转 AirPlay 后
连续接收 60 秒音频和多次大封面，7,517 包零丢失。

测试使用生成音频和隔离模拟器。详情见[验证记录](https://github.com/tiansongyu/cloudtune-nx/blob/v0.3.0/docs/VALIDATION.md)。首次下载、网络中断、损坏音源和
超出内存预算的文件仍可能需要缓冲或报告错误；不宣称所有游戏和手机已经通过实机验收。
