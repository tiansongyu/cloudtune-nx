# CloudTune NX v0.2.2 · 原生音乐界面与后台稳定性更新

## 界面

- 全新的深色音乐界面：侧栏导航、四列歌单、常驻播放栏、黑胶与滚动歌词，适配 1280×720 和 1920×1080。
- 统一白色焦点与品牌红色选中态，补齐手柄、键盘和触摸入口；收起播放器和返回歌单时保留原来的位置。
- 加入页面、封面、菜单与歌词过渡；设置中可减少动态效果，选择 100%／95%／90% 画面范围。
- 保留 Borealis / C++ 架构及现有音频、网络、账号和后台接口。公开安装包使用通用主题，不包含私人照片。

## 修复

- **覆盖层通信**：普通请求增加 150 ms 等待上限，服务获取使用独立 SM 会话；断连后降低重连频率。超时不重放控制命令，并安全处理迟到回复、句柄和仍被系统占用的缓冲区。
- **资源不足**：限制 MP3／FLAC 解码分配和 FFmpeg 单次分配，限制缓存清理时保留的候选数量。内存分配失败后释放当前资源并提示错误，播放器仍可接受新曲目；修复队列文件在分配失败时的句柄泄漏。
- **音频恢复**：输出失效或长时间没有释放缓冲区时，最多尝试重建三次，并恢复同一首歌的已播放位置。连续失败后暂停并提示重试；AirPlay 丢弃恢复期间积压的音频。
- **桌面验证环境**：清理音频工作线程的 SDL 线程本地资源，修复故障测试发现的泄漏。
- **互通复查**：修正异步客户端拒绝现有后台回复的问题；有效的业务错误不再被客户端误判为通信断开。
- **恢复边界**：修复恢复中跳转的状态、AirPlay 结束后的原曲进度，以及曲尾缓冲停滞和持续调音量阻止恢复的问题。
- **控制路径内存**：命令队列启动时预留容量，为投送结束保留位置；服务入口捕获异常并返回错误，避免退出后台进程。

## 使用说明

同步更新客户端、后台服务与覆盖层，然后重启。已有账号、设置和缓存目录应保留。

如果后台永久不回复，退出覆盖层时会结束本次覆盖层进程，以免系统继续访问已回收的通信内存；需要重新启动覆盖层加载器，并处理无响应的后台服务。
音频设备持续不可用时，检查输出设备后按播放重试。
