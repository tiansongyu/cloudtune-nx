# CloudTune NX v0.2.12 · 前后台通信与启动诊断修复

参考 TriPlayer 的标准 libnx 会话、进程检查和串行通信方式，修复后台延迟启动后的连接恢复，保留现有播放引擎、账号数据和 IPC 协议。

- 前台和覆盖层改用标准 TLS/CMIF 通信。独立工作线程限制调用方等待时间；超时命令不自动重发，迟到回复和会话句柄安全回收。
- 启动前先检查后台进程；后台正在启动或状态不明时，避免同时启动前台播放／AirPlay 实例。连接丢失后定期重试。
- 服务返回“暂不支持”或“队列已满”等有效错误时保留连接，其他控制仍可使用。
- 界面明确显示“后台连接中”；覆盖层提供连接阶段与错误码。启动时清理旧 IPC 日志，资源不足退出会给出具体提示。

请同时更新 NRO、后台 `exefs.nsp` 和覆盖层 `CloudTune.ovl`，然后完整重启。公开包不含私人照片，开机自启仍为可选；本机自启修复包保留照片并包含 `boot2.flag`。

实机日志已确认，上一版未注册服务是因为系统共享内存只剩 **168 KiB**。本版保留资源防护，需要关闭不使用的其他常驻模块释放内存；仅修改 IPC 无法消除该资源不足。

宿主回归、Switch 三组件构建与独立模拟器原生 IPC 探针已验证，详细范围见 [VALIDATION.md](../VALIDATION.md)。实机后台播放、游戏共存和 Ultrahand 控制仍需在释放内存后复测；模拟器结果不替代实机验收。
