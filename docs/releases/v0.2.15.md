# CloudTune NX v0.2.15 · 前台连接后台时报 0x10801

修复后台已启动、覆盖层能连接，主应用却一直显示“后台未就绪”的通信问题。
旧客户端额外创建一条 `sm:` 会话；Atmosphère 的应用模式只允许创建一个
会话，而 libnx 启动时已经占用，因此额外连接返回 `0x10801`。

- 参照 TriPlayer，复用 libnx 已注册的服务管理器会话，不额外占用创建额度。
- 保留后台请求超时、迟到回复回收、独立播放会话和安全退出；超时清理不会
  关闭 libnx 的共享会话，等待期间也不会进入可能阻塞的 PM 重复查询。
- 新增 `ipc-client-app.log`、`ipc-client-overlay.log`，记录版本、失败步骤、
  错误码与接受的控制命令。限制日志大小，不记录账号、曲目链接或请求内容。
- 包含此前 v0.2.14 本地候选版的受限内存启动修复：2 MiB 堆上限与 3 MiB
  系统策略余量。v0.2.14 因这次实机反馈取消公开发布。

请同时覆盖安装 NRO、后台 `exefs.nsp` 和 `CloudTune.ovl`，并重启 Switch。
保留 Tesla／Ultrahand 加载器自启。公开包不包含私人照片，仍默认按需启动；
已启用 CloudTune 自启的用户保留现有 `flags/boot2.flag` 即可。

原生模拟器通过实际内核配额复现旧连接返回 `0x10801`，相同限制下新客户端
握手、双客户端控制、超时恢复和退出重连通过。独立端到端探针使用真实后台
分发与播放引擎，经 IPC 交接队列后播放生成的 HTTPS MP3／AAC／FLAC，并验证
覆盖层暂停、前台恢复、切歌与清空队列。模拟器不代表实机游戏共存验收。
测试范围与实机待验证项目见 [验证记录](../VALIDATION.md)。
