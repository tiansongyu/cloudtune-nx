# v0.2.5 焦点与封面修复记录

## 原因

`MusicView::activate()` 在异步打开歌单后立即清空焦点，但旧榜单页面仍在显示，导致选中第三张卡片后瞬间高亮第一张。返回操作又会先恢复焦点、最多等 200 ms 才刷新画面，两者也可能不一致。

旧封面缓存按文件路径顺序淘汰。NanoVG 在帧末才提交绘制，因此在后面的 `cover()` 中删除纹理，会使本帧前面已经排入绘制的封面失效。超过 48 张图片后，这种删除可能反复发生。另外，解码失败的纹理 ID 0 被永久缓存，文件随后可用也不会重新加载。

## 实现

- 打开歌单时保留旧页面选择，由 `reconcile()` 在接收目标页面时建立新焦点；页面快照与焦点一起更新。
- 图片条目记录最近绘制帧。新帧开始时按最近使用情况回收至 48 项；本帧的新图片可以暂时超出容量，超出量受可见控件数限制，不在绘制过程中删除纹理。
- 加载失败的可见纹理最多每秒重试一次。歌曲封面实际可用后才启动淡入，支持异步元数据 / 图片到达。
- 所有前台播放入口共用首次播放分支。当前无歌曲时，歌曲列表使用原有 `play(0)` / `play_queue(0)`；卡片页使用原有 `open()`，目标歌单的页面、账号、ID、类型均匹配后才调用 `play(0)`。返回或失败会取消待播放请求。

## 本地回归

- 修复前的生产视图测试分别复现“第三张榜单焦点跳到第一张”和“加载第 49 张图片删除本帧已使用纹理”；修复后通过。
- 原生 OpenGL 测试使用仓库图标生成临时图片文件，验证满缓存重绘、可见纹理保持、首次文件不存在而随后可用时自动恢复。测试不依赖私人照片或外部下载。
- 首次播放检查当前列表第一首、规范队列、空列表、重复按键、加载等待、失败及返回取消。
- 完整桌面 CTest：25 / 25 通过。Switch NRO、后台 NSP、覆盖层均构建通过。
- 原生页面检查 720p / 1080p。Eden 的新配置使用实际私有 NRO 和匿名服务数据：首页按 Y 后播放第一个推荐歌单的第一首，随后暂停保留当前曲目。30 FPS 榜单进入录像的 240 帧中，第三张卡片被选中后未再跳回第一张；返回后仍选中原创榜。
- Eden 连续浏览全部 64 张榜单卡片后返回第一行，卡片和当前歌曲的小播放器封面均正常显示。

验证图片、录像、构建日志与私有产物保留在忽略的 `build/validation/ui-refresh/` 及 `build/validation/ui-refresh-*.log` 中，不随公开仓库或 Release 上传。公开包由干净检出构建，不包含本机私人照片。模拟器结果不代替实体 Switch 与游戏共存验收。
