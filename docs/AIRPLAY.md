# AirPlay 1 音频接收

CloudTune NX 的 AirPlay 1 工具将同一局域网内发送端的音频交给 Switch 播放引擎。
它独立于网易云账号和音乐 API，使用经典 RAOP 音频协议。本文描述当前开发分支；
已发布安装包的具体功能以对应发布说明为准。

目前已通过独立发送端到桌面程序的投送、加密协议测试及 Switch 编译验证；
真实 iPhone 到 Eden 内 NRO 的投送也已由用户确认正常出声。
其他 Apple 设备兼容性、实机 Switch 音频输出、退出 NRO 后继续投送和游戏同时运行
仍需验收，不能由模拟器测试推断通过。模拟器配置见 [Eden 指南](EMULATOR.md#airplay-1-from-a-phone-to-the-nro)。
本项目没有 Apple 官方认证，也不提供 AirPlay 2、视频、屏幕镜像或多房间同步。

## 使用

1. 将发送设备与 Switch 接入同一个允许设备互访的局域网。
2. 打开 CloudTune NX，进入「设置 → AirPlay 1 接收」。
3. 确认状态已就绪，并查看实际设备名与 IP 地址。默认名称为 **CloudTune NX**。
4. 在发送设备的音频输出列表中选择该设备。发送端需支持经典 AirPlay 音频投送。
5. 结束时，可在发送端取消投送，或在 CloudTune NX 中选择「断开当前会话」。

首次启动默认开启接收；之后按保存的偏好启动。关闭接收后，下次启动保持关闭。
开启偏好与实际监听状态是两件事：端口被占用或网络尚未就绪时，对话框会显示错误，
不会把保存偏好等同于监听成功。保持开启时，接收器每 2 秒自动重试获取网络并监听；
修复网络或释放端口后无需手动关闭、开启。

| 控制 | 行为 |
| --- | --- |
| 开启接收 | 保存开启偏好并尝试启动发现与监听 |
| 关闭接收 | 结束会话、停止发现与监听，并保存关闭偏好 |
| 断开当前会话 | 等待接收线程确认会话已断开，保留接收开关 |
| 播放 / 暂停 | 本地暂停或恢复音频输出；暂停期间的数据不会积压后重放 |
| 音量 | 本地音量与发送端音量共同作用 |
| 选择网易云曲目、上一首 / 下一首、停止 | 先结束当前投送，再执行网易云播放控制 |

AirPlay 是实时音频，播放器的跳转操作不能调整发送端的播放进度。
Switch 上的暂停只停止本地输出，手机的播放进度可能继续前进；恢复时接收最新音频。
要同时暂停手机，请在手机上操作。当前没有实现向发送端回传播放控制的 DACP 通道；
这不是经典 AirPlay 协议必然的限制，发送端是否支持遥控也因设备和播放器而异。
发送端提供曲目信息时，可显示标题与歌手；此信息不代表网易云队列中的歌曲。
同一时间只接受一个发送端会话，不混合网易云和投送音频。
投送结束后保留原网易云队列及接管时的播放位置，恢复为暂停状态；按播放继续。

## 前台与后台

| 当前模式 | 接收进程 | 退出 NRO 后 |
| --- | --- | --- |
| BGM · 后台服务 | Atmosphère 中的 `cloudtune-background` | 服务继续存在，按接收偏好运行 |
| 前台播放 | NRO 内的本地 Runtime | 本地接收和音频一起停止 |

NRO 优先连接后台服务，不为已存在的服务重复建立接收器。后台仍是旧版本时，
音乐播放可以继续使用；AirPlay 对话框会提示更新后台服务。同步替换安装包中的
`atmosphere/contents/42000000004E434D/exefs.nsp` 并重启，避免只更新 NRO。

启用 `boot2.flag` 后后台会在开机时启动，通过 HOME 和资源检查后再按保存偏好开启 AirPlay。
公开安装包默认不带该标志；自启补丁包含它。
需要停止监听时，在设置中关闭接收。移除 `boot2.flag` 并重启会停止开机自启，
但打开 NRO 时仍会尝试按需启动服务。详情见 [安装指南](INSTALLING.md)。

“退出 NRO 后服务继续存在”不代表主机休眠时仍可接收。网络切换、睡眠唤醒、蓝牙耳机、
底座切换以及与游戏共存均属于 [实机验收](HARDWARE_TESTING.md) 范围。

## 网络与设置文件

接收器发布 `_raop._tcp` mDNS 服务，使用 UDP 5353 发现，默认 TCP 5000 处理控制连接。
音频、控制和时钟同步使用会话协商的 UDP 端口。访客 Wi-Fi、AP 隔离、跨子网和
阻止组播的防火墙可能使设备不可见；仅开放 TCP 5000 不足以完成完整音频会话。
当前没有配对码或访问密码，应在自己信任的局域网启用。

自动选择接口时，接收器每 3 秒重新检测 IPv4 地址。地址改变会结束旧会话、
更新服务发现并重新绑定监听；发送端可能需要重新选择设备。显式配置 `address`
用于固定接口或测试，不启用自动地址切换。

设置保存在兼容的数据目录中，与网易云 `settings.json` 分开：

```text
sdmc:/config/netease-switch/airplay.json
```

宿主版本使用 `CLOUDTUNE_DATA` 指定的数据目录，并兼容 `NETEASE_SWITCH_DATA`。
`airplay.json` 使用已有持久化层及备份恢复；关闭接收会保存 `enabled: false`。
正常操作无需手动修改文件。需要调试时，先停止所属进程，再修改以下字段：

| 字段 | 默认值 / 用途 |
| --- | --- |
| `enabled` | `true`；是否在 Runtime 启动时开启 |
| `name` | `CloudTune NX`；非空，最多 40 个 UTF-8 字节，无换行 |
| `device_id` | 首次生成的 12 位十六进制标识；用于保持设备身份 |
| `port` | `5000`；控制端口，范围 1024–65535 |
| `address` | 空；自动选择 IPv4 接口。测试可指定本地 IPv4 |
| `advertise` | `true`；发布 mDNS。关闭仅用于直接连接的隔离测试 |

无需移动或删除现有登录目录。不要将包含账号会话的数据目录上传到问题报告。

## 实现与兼容边界

接收器在 `airplay/` 内独立实现 RTSP、RTP 音频接收、时钟同步、重传请求、
经典协议的 RSA/AES 处理和 mDNS。ALAC 解码使用固定版本 FFmpeg 7.1.5，
仅启用所需解码器；立体声 16 位 PCM 经有界缓冲进入唯一的音频工作线程。
最终 PCM 交接缓冲为 24,000 帧（48 kHz 时约 500 ms）；网络抖动由接收器的
时间戳包队列处理。小包聚合成完整输出块，避免每个约 8 ms 的包占用一次音频提交。
ALAC 接受 44.1 / 48 kHz，原始 L16 接受 44.1 kHz；输出统一重采样至 48 kHz。
网易云文件播放器另有 MP3 / AAC / FLAC 解码路径；AirPlay 接收不依赖当前网易云账号。
切换或移除网易云账号会清空原音乐队列，已在进行的 AirPlay 投送可以继续。

`background::Runtime` 负责接收器、音乐引擎和 `airplay.json` 的生命周期；
接收线程不直接调用 SDL 或 Switch `audout`。新工具状态为独立的
`NcmAirplayStatus`，使用 IPC 命令 30、31、32。原音乐状态仍为 216 字节，
旧覆盖层的音乐协议保持不变；覆盖层无需加载网络接收器或解码库。

后台根据启动时资源选择普通模式（堆上限 16 MiB、系统策略余量 8 MiB）
或受限模式（堆上限 2 MiB、系统策略余量 3 MiB），并在增长前检查资源。
受限模式下较大的解码或队列分配可能失败；模式在本次服务运行期间不变。
关闭接收后释放接收器对象并尝试回收空闲堆尾。内存不足时设备下线通知可以省略，
仍会关闭 socket，清理和错误状态更新不会为了生成字符串再次分配内存。
这不等于实机稳定性或峰值内存已验收。依赖来源、兼容密钥说明和许可证见
[第三方声明](../THIRD_PARTY_NOTICES.md)。

## v0.3.0 的封面接收修复

2 MiB 受限模式下，旧接收器整段缓存并复制控制请求正文。持续投送时收到
256 KiB 封面可触发内存不足，导致接收线程退出。v0.3.0 每次最多读取 4 KiB，
分块消费不显示的封面，保留正确的请求长度、应答和后续消息边界。每轮最多
处理 32 KiB 控制数据，给音频包接收留出运行机会。正文总上限仍为 512 KiB；
需要解析的 SDP、文本参数和 DMAP 元数据限制为 16 KiB。

不再用整张封面占用后台堆，并不代表手机兼容性已全部验收；真机网易云
AirPlay 与游戏共存仍需安装后复测。原生测试使用生成的 ALAC 和封面，不使用
用户手机或账号。

## 排查与验证记录

- **状态未就绪：** 查看对话框的实际 IP 和错误；确认 Wi-Fi、端口占用和存储可写。
  开启状态下网络或端口失败会每 2 秒自动重试；设置文件错误需先修复文件。
- **发送端找不到设备：** 检查是否同一局域网、mDNS 是否可达、是否有访客网络隔离。
- **可以连接但无声：** 检查本地与发送端音量、暂停状态以及发送端所用协议。
- **退出应用后停止：** 确认处于后台服务模式，并使用配套的新版 `exefs.nsp`。
- **旧服务提示：** 同步更新 NRO 与后台组件并重启；不要额外启动第二个接收进程。

已运行的本地 `airplay_audio_tests` 使用生成的 MP3 和 PCM，不接触用户账号、
现有播放服务或手机。检查覆盖有界缓冲、44.1→48 kHz 重采样、暂停期间丢弃旧数据、
清空缓冲、独占接管，以及断开后保留网易云位置并手动恢复。
Player 的独立替身测试另检查并发控制、退出后的生命周期及旧后台兼容。
独立 RAOP 测试已通过加密 ALAC 与 L16 的逐样本结果核对、协议挑战响应、
时钟交互、重传、FLUSH、PAUSE、元数据、单会话所有权及畸形请求拒绝。
端口占用后的自动恢复与等待期间及时退出也已通过本地协议测试。
未修改的 pyatv 发送端另通过 mDNS 发现实际程序并完成 45 秒投送；设置开关、
重启保存、播放页曲目信息和黑胶暂停/旋转均在隔离虚拟桌面中检查。
音频测试使用 SDL 虚拟输出，不代表扬声器音质或实际手机投送通过。详细结果记录在
[验证报告](VALIDATION.md) 和 [开发日志](DEVELOPMENT_LOG.md)。
